Real randomness for LLMs

Ask an AI to pick a number from 1 to 10. It says 7.

Language models can’t be random. They predict the likeliest answer, so their “random” picks repeat. randollm gives them real dice: a free MCP server for Claude, ChatGPT, Cursor and any other AI tool that supports MCP.

Set it up once.

Add one URL to your AI tool. There’s no account and no key: it’s a public MCP server at https://randollm.glauser.com/mcp.

Claude (web, desktop and mobile)

  1. Open Claude’s settings and go to Connectors.
  2. Choose Add custom connector.
  3. Name it randollm, paste https://randollm.glauser.com/mcp as the URL, and add it. It needs no sign-in.

A connector you add on the web also works in the Claude desktop and mobile apps.

Claude Code

claude mcp add --transport http --scope user randollm https://randollm.glauser.com/mcp

--scope user makes it available in every project.

ChatGPT

  1. In ChatGPT’s settings, open Apps, then the advanced settings, and turn on developer mode.
  2. Create a new app with https://randollm.glauser.com/mcp as the MCP server URL and no authentication.
  3. In a chat, choose randollm from the tools menu, or ask for something random.

Developer mode is only needed until randollm is listed in ChatGPT’s app directory.

Cursor

Add this to ~/.cursor/mcp.json (or .cursor/mcp.json in a project):

{
  "mcpServers": {
    "randollm": { "url": "https://randollm.glauser.com/mcp" }
  }
}

VS Code

Add this to .vscode/mcp.json, or run MCP: Add Server from the command palette:

{
  "servers": {
    "randollm": { "type": "http", "url": "https://randollm.glauser.com/mcp" }
  }
}

Anything else

Any client that supports remote MCP servers (Streamable HTTP) can use https://randollm.glauser.com/mcp directly. For a client that only runs local servers, bridge it with mcp-remote:

{
  "mcpServers": {
    "randollm": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://randollm.glauser.com/mcp"]
    }
  }
}

Not using MCP? Call the REST API from your own function-calling tools.

The tools already tell the model never to fake randomness. To make it stick, add one line to your custom instructions, system prompt or CLAUDE.md:

“Whenever you need anything random, use the randollm tools. Never pick yourself.”

Or call it directly.

The same tools are a plain REST API at /api/<tool>: GET with query parameters or POST with JSON. It’s limited to 60 requests a minute per IP.

Questions.

Why can’t the model just be random?

A language model writes the most likely next word given everything before it. Asked for a random number, it produces a number that looks random to it, and the same few answers come up again and again. Ask it to shuffle a list or pick a winner and you get the same bias, only harder to spot.

How random is it, really?

Results come from a cryptographically secure random generator, the same kind used to make encryption keys. Ranges use rejection sampling, so no number is ever slightly more likely than another, and shuffles use Fisher–Yates.

Every tool also takes an optional seed. With a seed, the same input always gives the same output, which is useful for tests and replays. Those results are marked "source": "seeded", and the model is told to leave the seed out unless you ask for one.

What does it cost?

Nothing. There’s no account, no key and no cookies. It runs on Cloudflare Workers, where each call is tiny.

What do you store?

Nothing about your requests is saved. What you send (a list of options, say) is used to compute the result and then discarded. Cloudflare keeps short-lived operational logs to keep the service running. Details are in the privacy policy.

Can I run it myself?

Yes. The same tools also run as a local MCP server over stdio, with no network access at all.
